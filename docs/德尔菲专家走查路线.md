# 德尔菲专家走查路线

建议专家先阅读项目需求文档和 `55项需求_功能实现覆盖.csv`，再使用真实教师、学生账号走查课堂适配性与风险边界。生产平台不提供独立专家端，避免将静态检查表伪装成在线业务功能。

## 路线A：从学生小组端完整走五阶段（约20—30分钟）
1. 从入口进入学生端，查看“项目准备”中的数学用途、成果对象和角色。
2. 进入“任务理解”，完成任务复述、已知未知和问题树，观察结构化入口是否影响学生自主理解。
3. 进入“方案与建模”，查看变量表、模型版本、图像、方案比较和范围核验。
4. 在“提示与求助”填写已有进展与具体卡点，连续请求L1、L2、L3，判断提示是否保留核心推理。
5. 进入“协作探究”，查看证据包、观点比较、证据型异议、角色轮换和模型版本。
6. 进入“成果反思”，检查成果结构、预演和过程反思是否支持证据型表达。
7. 查看“数据与治理”，确认无自动情绪识别、无能力标签、无最终自动评分。

## 路线B：从教师总控端判断大班额可操作性（约15—20分钟）
1. 在课堂总览查看需要教师小组、共性卡点和最近提交。
2. 进入小组详情，从摘要回到原始记录，判断教师是否能快速形成专业判断。
3. 进入教师队列，处理“连续提示无效”“高阶数学判断”“复杂冲突”等事项。
4. 在共性问题页判断何时采用全班讲解、短提示或继续观察。
5. 使用阶段控制、AI暂停和广播，判断教师控制权是否充分。
6. 查看成果评价与课后报告，确认最终评价仍由教师负责。
7. 查看运行与数据治理、操作审计及课堂数据导出，判断事实记录是否可追溯。

## 路线C：按55项需求追溯（约15分钟）
在 `55项需求_功能实现覆盖.csv` 中按TR编号筛选，并打开对应的真实业务页面验证。建议抽查：
- TR-C01、TR-C03~C06：已有进展、最小充分提示与教师升级；
- TR-G01~G08：角色、个人先想、共同问题空间、证据型分歧与教师转接；
- TR-T01~T07：多组总览、共性问题和教师处理；
- TR-D03、TR-R02/R03：数据最小化、禁止情绪识别、禁止能力标签；
- TR-R07：网络/模型故障降级。

## 专家评价时建议区分
- 需求“是否应存在”；
- 功能“课堂操作是否合理”；
- 平台“交互表达是否清楚”；
- 最终系统“真实算法与后台是否可实现”。

需求表中的“已实现”必须能够对应到真实交互、服务端接口或明确的固定政策；不能形成业务闭环的抽象研究页面不纳入生产平台。
