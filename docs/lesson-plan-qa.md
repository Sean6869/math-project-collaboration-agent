# 教案解析与多课时配置验证

日期：2026-09-12。仅本地验证，未部署生产环境。

## 实现边界

- 教师独立上传教案、后台解析、结果预览、逐课时编辑、审核后显式发布。
- 原教案与解析任务存储在教师私有表，不加入学生文件列表或知识库；原文件下载需验证上传者身份。
- 课时与五个项目阶段分离。发布使用独立版本和事务，不更新学生工作区、阶段提交、角色或对话；旧全量状态保存不能撤销新发布的项目字段。
- 学生端和两类AI读取同一份已发布课时；网页轮询只更新课时信息，不重绘正在编辑的学生表单。
- PDF文字、表格和图片页联合输入；DOCX图片未解析时明确提示。解析失败/输出截断/时长不一致不伪装成功。

## 真实豆包测试

使用用户提供的《小小采购员》14页PDF和临时密钥，调用当前配置的豆包文本/视觉接口两次。

- 提取14页、含表格文本约1.38万字，第2、8、10、11页进行视觉识别。
- 第一次调用约63秒，发现自由文本安排改变了个别活动时长，随后增加原文活动与课时分配的结构化时间校验。
- 第二次调用约70秒，通过结构校验，识别4课时、每课时40分钟，总计160分钟；原文7项活动的分钟数逐项守恒。
- 识别三年级与四年级知识冲突并提醒；未明示的项目类型保留空白。

| 课时 | 原文活动时间分配 | 合计 |
|---|---|---|
| 1 | 活动1：20；活动2：20 | 40分钟 |
| 2 | 活动3：30；活动4：10 | 40分钟 |
| 3 | 活动4：10；活动5：20；活动6：10 | 40分钟 |
| 4 | 活动6：10；活动7：30 | 40分钟 |

该结果不是普遍正确性的保证，教师仍需核对活动可行性、年级适用性和学生可见内容。模型耗时也不是固定承诺。

## 回归验证

- Python自动化：32项通过，覆盖真实HTTP鉴权、后台任务、失败保留、重启恢复、发布版本冲突、阶段/学生记录不变、原文时长核对、两类AI课时上下文和原有功能。
- 浏览器测试：模拟结果与真实豆包结果均验证了填入、逐课时编辑、审核阻拦、显式发布、上传失败重试和学生课时同步；桌面1440像素与手机390像素无横向溢出，检查了提醒可见性。
- 页面冒烟：45个页面、静态资源及健康接口通过。
- 测试数据为隔离环境；未改动线上课堂。密钥仅在被Git和Docker忽略的本地`.env`中，真实解析样本仅保存在忽略的本地`data`目录。

运行：`python -m unittest discover -s tests -v`、`python tests/smoke_pages.py`。浏览器回归需Playwright：`node tests/lesson_plan_ui.cjs`。用真实解析JSON复验页面可设置`MAPLE_LIVE_PLAN`为该本地JSON路径。
